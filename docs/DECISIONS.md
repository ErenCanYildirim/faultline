# Decisions log

One line per decision: what, why, and when it gets re-checked. This becomes the trade-offs section of the README in Phase 3.

| # | Step | Decision | Why | Re-check |
| --- | --- | --- | --- | --- |
| 1 | 1.1 | One Go module for everything, SDK included | Simplest to build and refactor while the API is moving | Before publishing the SDK: split it into its own module so apps importing it don't see server dependencies in their module graph |
| 2 | 1.1 | SDK package is named `faultline`, in folder `sdk/` | Calling code reads `faultline.CaptureError(err)`, not `sdk.CaptureError(err)` | — |
| 3 | 1.1 | One multi-stage Dockerfile, service picked by build arg | One place to change the Go version and base image | — |
| 4 | 1.1 | Distroless runtime image, binary does its own healthcheck | No shell or curl in the image; smaller attack surface | — |
| 5 | 1.1 | `events.raw` with 6 partitions, replication 1 | Room for up to 6 workers on one PC; single node can't replicate | Phase 3 benchmark |
| 6 | 1.1 | `events.raw` retention 1 day, `events.dlq` 7 days | ClickHouse is the store; the topic only buffers. 1 day covers any outage you'd test locally | Phase 3 failure tests |
| 7 | 1.1 | Topic init is idempotent and never changes an existing topic | Safe on every `up`. Changing partitions is a deliberate act (`rpk topic add-partitions`) | — |
| 8 | 1.1 | Redis without persistence | Rate-limit buckets are seconds-long state; losing them on restart only resets limits | Phase 2 |
| 9 | 1.1 | All ports bound to 127.0.0.1 | Dev passwords; nothing should be reachable from the LAN | — |
| 10 | 1.1 | PowerShell `tasks.ps1` instead of a Makefile | Development happens on Windows, where `make` isn't installed by default | When CI is added: a Makefile or CI script for Linux |
| 11 | 1.2 | JSON wire format, snake_case fields | Easy to debug with curl and logs | Phase 3 benchmark (binary format) |
| 12 | 1.2 | `event_id` is UUIDv7 generated by the SDK | Same ID on every retry enables dedupe; time-ordered IDs sort well in ClickHouse | Phase 1 |
| 13 | 1.2 | `project_id` and `received_at` are set by ingest only | A client must never be able to write into another project or fake server time | — |
| 14 | 1.2 | Frames ordered innermost first | Matches Go stack output; "top N frames" for grouping is a simple prefix | Phase 2 |
| 15 | 1.2 | One exception per event, no chained exceptions | Go wraps errors into one message; a chain adds schema complexity for little gain now | Known limitation |
| 16 | 1.2 | SDK truncates to limits, ingest rejects per event, not per batch | Good clients never lose data to size limits; one bad event doesn't sink 99 good ones | Step 1.4 |
| 17 | 1.2 | Out-of-window timestamps are replaced with `received_at`, not rejected | A wrong client clock shouldn't lose an error report | Implemented in 1.4 |
| 18 | 1.3 | SDK has no third-party dependencies (own UUIDv7, stdlib HTTP and gzip) | Every dependency of an SDK becomes a dependency of every app that imports it | — |
| 19 | 1.3 | Bounded buffer as a buffered channel; capture uses a non-blocking send | The simplest structure that guarantees "never blocks"; the bound is the channel capacity | 1.3b adds a byte bound |
| 20 | 1.3 | Buffer full: drop the new event, keep the old ones | The first events of an incident are usually the most useful; the newest are mostly repeats | Phase 3 failure tests |
| 21 | 1.3 | One sender goroutine, batches by size or interval, whichever comes first | One goroutine means one request at a time and no locking on the send path | Phase 3 benchmark (parallel senders) |
| 22 | 1.3 | Flush drains only what was queued at the moment it was called | Under steady load the queue never empties; a flush must still finish | — |
| 23 | 1.3 | `Recover` captures, flushes for up to 2s, then re-panics | The SDK records crashes; it must not change program behavior by swallowing them | — |
| 24 | 1.3 | Error type = deepest specific type in the `Unwrap` chain | The outermost type is usually `*fmt.wrapError`, the root is often a plain sentinel; both group unrelated errors together | Phase 2 grouping tests |
| 25 | 1.3 | Stack captured at the `CaptureError` call, not where the error was created | Go errors don't carry stacks. The capture site is usually the handler that saw the error; the creation site is lost | Known limitation |
| 26 | 1.3 | Stats keep every captured event in one place: `Captured = Sent + Failed + Queued + InFlight` | Lets the Phase 3 loss checker account for every event on the client side | — |
| 27 | 1.4 | Project key in `X-Faultline-Key` header, not the URL | Query strings end up in access logs and proxy logs | — |
| 28 | 1.4 | Keys looked up by SHA-256 hash; at least 16 characters | Removes timing differences from the lookup; short keys are guessable | — |
| 29 | 1.4 | Two body caps: 1 MiB on bytes received, 1 MiB after decompression | The second stops a small gzip bomb from expanding in memory | — |
| 30 | 1.4 | 202 only after the broker acknowledged every event of the request (acks=all) | A 202 means durable. Anything less loses events silently when the broker restarts | Phase 3 failure tests |
| 31 | 1.4 | Broker failure: 503 + `Retry-After` for the whole batch, even if part of it was written | Partial-success bookkeeping is complex; the retry may write duplicates, which dedupe by `event_id` removes | Phase 3 failure tests |
| 32 | 1.4 | Produce timeout 5s, below the SDK's 10s HTTP timeout | A broker outage reaches the client as a 503 it can act on, not as a client timeout | 1.3b (retry timing) |
| 33 | 1.4 | Queue key = `event_id` | Spreads load evenly across partitions; ordering between events isn't needed | Phase 3 benchmark |
| 34 | 1.4 | Readiness pings the broker, liveness doesn't | A broker outage should take ingest out of a load balancer, not get it restarted in a loop | — |
| 35 | 1.4 | Automatic topic creation turned off in Redpanda | A typo in a topic name must fail loudly, not silently write to a new topic | — |
| 36 | 1.4 | Ingest depends on a `queue.Producer` interface, not on Kafka | NATS (Phase 5) becomes a second implementation instead of a rewrite | Phase 5 |
